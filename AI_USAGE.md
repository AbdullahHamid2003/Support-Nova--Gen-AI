# AI tool usage declaration

SRS section 18 requires every AI tool used during development to be declared here. There are two
separate kinds of AI in this project:

1. **AI inside the product** (required by the SRS architecture): the GenAI API that Pipeline 1 calls at
   runtime.
2. **AI used to build the product:** a coding assistant.

## 1. GenAI API used by the application (runtime)

| Item | Detail |
|---|---|
| Tool | OpenAI API, model `gpt-4.1-mini` (default; `AI_PROVIDER` / `AI_MODEL`). Anthropic and Google Gemini adapters are included and selected by configuration only. |
| Purpose | Pipeline 1: (a) structured complaint analysis (`prompts/complaint_analysis/`), (b) the customer response written from the Python-validated decision (`prompts/customer_communication/`). |
| Where | `backend/src/supportnova/genai_pipeline/` (providers, prompt rendering, JSON schemas, retries) |
| Controls | The key stays server-side (`.env.secrets`, never sent to the browser or committed). Outputs are validated against JSON schemas and then checked field by field by the independent Python pipeline (`python_validation/`, `rule_engine/`, `hallucination_checks/`). Every call is logged with prompt version, model, latency, tokens and the raw response (`ai_runs` table, **AI runs** tab). Without a key the step reports `not_configured`: no output is fabricated. |
| Testing | Adapter tests against fake vendor servers (`tests/backend/unit/test_genai_providers.py`); live runs against OpenAI (the demo dataset and the 154-case holdout evaluation in `reports/genai_python_comparison/`). |

## 2. AI assistance during development

| Item | Detail |
|---|---|
| Tool name | Claude Code (Anthropic), running the Claude Opus model family |
| Purpose | Design and implementation of the application from the SRS; test writing; debugging; documentation |
| Type of assistance | Code generation and refactoring; test generation; running tests, linters and type checks and fixing what they found; generating the synthetic dataset and knowledge-base documents from their specifications; analysing live GenAI runs and fixing the issues they showed; writing documentation |
| Files affected | Most of the repository: `backend/src/supportnova/**`, `frontend/src/**`, `rules/**`, `config/**`, `prompts/**`, `schemas/**`, `knowledge_base/**`, `data/**` (generated by `scripts/generate_dataset.py`), `scripts/**`, `tests/**`, `docs/**`, `README.md`, deployment files (`Dockerfile`, `docker-compose.yml`, `render.yaml`) |
| Modifications made | See the git history. Each commit describes one change and why it was made, e.g. the fixes found by the live OpenAI runs (catalog-restricted schema, prompt 1.1.0, paraphrase-aware claim grounding) and the removal of the development mock provider. |
| Testing performed | 206 backend tests (unit, API, integration, end-to-end; `pytest`), 12 frontend tests (`vitest`), `ruff`, `mypy`, `eslint`, `tsc`; live end-to-end runs with the real OpenAI model; the holdout evaluation; the adversarial lab; screenshots of every page with a browser console-error check (`scripts/capture_screenshots.py`) |
| Verifying team members | *To be completed by the team:* each member records which parts they reviewed, modified and tested, in the table below. |
